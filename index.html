03 — 项目

四个能说清楚取舍的案例

01

华为 Answer 2.0 AI 办公｜企业级 Agent 工作伙伴

产品经理 + 体验设计 · 双角色

S 背景
信息散在 WeLink 文档、群聊、知识中心与代码仓库，跨系统办事要反复复制粘贴；知识源有 3 个入口，全量用户中仅约 700 人使用且极易选错。
T 任务
以 PD + UXD 双角色负责能力边界、产品骨架、状态化交互与反馈闭环；目标是让用户只记一个入口、敢把任务交出去、失败时知道为什么。
A 行动
  • 确立「Chat 是入口、垂域是能力」，子代理封装为工具由主 Agent 调度。
  • 知识源三入口收敛为一个下拉；取消前端硬约束，改由 Agent 消解冲突。
  • 把状态写成枚举——无输出不出现复制/分享，失败不出现点赞。
  • 反馈改为两级标签，并自动映射到跟进人。
  • 内审推行「先画理想链路，再推架构」。
R 结果
  • 覆盖 近 1000 人，试点团队满意度 4.2；入口 3 → 1。
  • 反馈可定位：7.1–7.20 共 85 条，BUG 22 条，按模块分派。
  • 沉淀 Agent 设计体系 45 个组件。

锐捷 Source ID 3.0｜本体与数据产品

产品设计师 · 模块体验 / Agent 链路

S 背景
产品包含本体、数据管道、数据管理等专业模块，用户需要理解数据与本体之间的关系并完成配置构建，专业门槛高、跨模块任务不连贯。
T 任务
负责三个核心模块的体验设计，并参与 Agent 任务链路与设计规范建设；重点是降低专业能力的使用门槛，改善跨模块任务的连贯性。
A 行动
  • 梳理数据接入、加工、建模、管理的依赖关系，找出跨模块断点。
  • 用 Lovable 做原型探索，验证跨模块信息架构与关键操作路径。
  • 设计 Agent 任务链路（输入 → 任务理解 → 构建执行 → 结果确认），定义过程状态、异常反馈与人工介入。
  • 探索 Agent 辅助与手动操作的协同，避免复杂任务成为黑盒。
  • 沉淀任务流程与状态表达原则。
R 结果
  • 形成面向企业级复杂任务的 Agent 体验设计实践，兼顾配置效率、过程透明与人工控制。
  • 跨模块路径统一，Agent 过程可见、可回退。
